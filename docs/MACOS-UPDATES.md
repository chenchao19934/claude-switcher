# macOS 界面更新

新版「版本更新」页可更新 App、核心脚本及 STUN 探针。旧版只有检查和复制命令按钮，无法自行获得这项能力，需先替换一次新版 App 或使用安装器；之后无需再借助 AI 替换界面。

1. 点击「重新检查」。这是只读操作，不写账号、客户端日志、更新锁或安装文件。
2. 发现新版后，点击「更新并重启」并确认。更新器校验固定提交的源码和 SHA256 清单，在暂存目录编译并签名 App，保留原有五个代理／地区配置，运行完整 14 项安全检查。检查失败则中止，保持原安装版本。
3. 准备完成后，独立用户态进程接管更新，旧 App 退出，再备份并替换 App、核心和探针。新版 App 必须返回一次性启动确认；启动或替换失败则回滚，并尝试重新打开旧版。

更新源为 `chenchao19934/claude-switcher` 的 `main`。版本先解析为固定提交，再下载同一提交的源码包和清单，避免主分支变化造成校验竞态。清单必须覆盖核心、探针、桌面更新器、Swift 界面源码和图标；缺项或校验不符即中止。只修改界面或图标也会提示更新。

下载优先使用已配置的代理环境变量；没有时读取 macOS 已启用的系统 HTTP(S) 代理。网络错误只显示分类原因，不打印代理地址、IP 或凭据。不要关闭 TLS 验证或跳过 SHA256 检查。

需要 Xcode 命令行工具和 Python 3。App、核心、探针目录必须属于当前用户、可写、无符号链接并位于同一磁盘；系统受保护安装位置请使用安装器。正式签名或包含 Widget 的 App 需使用相同签名的发布包升级，本流程会拒绝将它们替换为 ad-hoc 版本。

账号数据与存档、检查设置、代理配置以及 root 所有的保镖和时区看门狗不参与替换。准备阶段的安全检查沿用正常 `checkdetail` 行为，会更新已有的最近检查记录。系统守护组件有变化时需另行运行安装器，不在用户态更新中提权部署。

暂存和备份位于 App 同目录的 `.claude-switcher-update-<事务编号>/`。成功后保留 `previous-app.app`、`previous-core.sh` 和存在时的 `previous-stun.py`，以及不含 IP／凭据的事务结果；失败时保留仍有恢复价值的备份。终端 `update` 的备份仍使用各工件的 `.bak`。确认更新完整成功前，不要删除备份或不明暂存目录。

界面更新与终端／12 小时核心自动更新共用 `~/.claude-switcher/.update.lock`，已有锁时拒绝并发，不自动删除不明锁。若系统强制断电或更新进程被不可捕获地终止，可能需要结合事务记录手动恢复并核对锁；不要在不确认备份和运行进程的情况下清理。

仓库测试使用临时 HOME、假网络、假编译和假 App 进程，覆盖校验、事务、重启确认和回滚。它们不能冒充真实安装态的端到端更新验收；维护者本机部署仍须当次明确授权。
